# 创作者研究与知识库收录

用于“读这个UP/博主的观点”“整理到知识库”一类任务。单篇摘要不必加载此文件。

## 确认来源

从分享链接核对创作者名称与稳定账号 ID。页面投稿数、合集数只作读取时快照；不将重叠合集相加为独立作品总数。

按用户重点选内容。范围尚未明确时，可以先阅读相关代表内容，再询问能改善结果的偏好。用户要求全量处理时，先建立实际取得的目录，逐条记录正文状态；没有实际遍历就不能称完整覆盖。

每条内容记录：标题、链接、创作者、发布日期、读取日、原创/搬运/引用、实际取得部分、未取得部分。评论与正文分别记录。来源日期与搬运日期不能混用。

## 视频原作者与正文

搬运描述直接给出原版时，可以访问原作者公开内容核对观点。保持搬运者与原作者两个字段；原视频中的“我”、项目经历和收入属于原作者。完整读完字幕后才能标“完整字幕已读”，不能称已逐镜观看或全部画面已分析。

数字、产品名和日期容易被自动字幕误识。对结论不必要的模糊精确数字，可以省略；保留需要再核实的状态。原版与搬运版时长不同，时间戳分别标注，不直接映射。

“放弃某项目”“预计发布”“融资”“发售”“盈利”是不同结果。历史计划有后续可靠结果时，保留原计划并增加新证据。收入案例区分销售、融资、众筹、到账和利润；原作者自述及第三方估算不能改写成用户结果。

## 写入现有知识库

1. 用户明确要求收录后，读取目标库现有 `AGENTS.md`、索引和相关入口；先检查同一来源，保留人工修订与原件。
2. 为实际已读来源写摘要，记录出处、作者、日期、阅读范围和时间戳。公开内容以自写摘要及必要短引文保存，不批量转载完整字幕。
3. 综合分析明确区分来源观点、跨来源对照、本库推断和建议行动。仅索引条目不能生成正文观点。
4. 只在有复用价值时提炼概念，链接来源与已有主题。没有读过用户工程或账目，就不更新其项目完成状态。
5. 更新目标库要求的索引、领域入口和日志，检查新增链接；报告实际处理数量、遗留缺口及状态。

没有既有目录规则时，用用户指定目录保存 Markdown 与来源索引即可，不替用户重建整个知识库。上传、同步或定时监控需属于用户明确授权的任务。
